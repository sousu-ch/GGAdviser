# カスタムプロンプト機能：反復的実装・検証計画書

本計画は、小さなステップ（実装）と、それを即座に確認するループ（検証）を繰り返すことで、確実かつ安全に機能を構築する。

---

## Phase 1: ストレージ基盤と定数管理
**目標**: データの保存場所を定義し、デフォルト値で正しく動作することを保証する。

- **Step 1.1: 定数と初期値の定義**
  - **実装**: `constants.js` に `PROMPT_TEMPLATE` キーとデフォルト定型文を追加。
  - **検証**: 拡張機能をリロードし、コンソールから `GG_CONSTANTS.PROMPT.DEFAULT` が正しく日本語で読み取れるか確認（文字化けチェック）。 [DONE]

- **Step 1.2: Storage アクセスロジックの確認**
  - **実装**: `background.js` で初期起動時に `chrome.storage.local` にデフォルト値をセットする処理を追加。
  - **検証**: コンソールから `chrome.storage.local.get` を実行し、定義した日本語テンプレートが正しく取得できるか確認。 [DONE]

---

## Phase 2: プロンプト置換エンジンの作成
**目標**: テンプレート内の `{{url}}` などを、実際のデータに置換するロジックを確立する。

- **Step 2.1: ユーティリティ関数の実装**
  - **実装**: `utils/PromptBuilder.js` [NEW] を作成し、正規表現による置換関数を実装。
  - **検証**: 背景スクリプトのコンソールで、テスト用テンプレートと仮のデータを渡し、期待通りの文章が生成されるか（サニタイズも含め）確認。 [DONE]

---

## Phase 3: 設定 UI (Popup) の実装
**目標**: ユーザーがブラウザ上で直接プロンプトを編集できる最小限の UI を提供する。

- **Step 3.1: 基本的な編集画面の作成**
  - **実装**: `popup.html` に `textarea` を配置。
  - **検証**: ポップアップを開いた時に、Storage から取得した現在の日本語プロンプトが正しく表示されるか確認。 [DONE]

- **Step 3.2: 保存処理の実装**
  - **実装**: 「保存」ボタンのクリックイベントと、Storage への書き込み処理を実装。
  - **検証**: `popup.js` を通じて保存した内容が、拡張機能を閉じてもう一度開いた時に保持されているか、また `chrome.storage.local` 内の値が更新されているかを確認。 [DONE]

---

## Phase 4: ライフサイクルへの統合（データ抽出フロー）
**目標**: Geoguessr 画面で [ANALYZE] ボタンを押した際に、カスタムプロンプトが使われるようにする。

- **Step 4.1: 抽出ロジックの改修**
  - **実装**: `background.js` または `geoguesser.js` の通信部を修正し、Storage からテンプレートを取得して置換エンジンに渡すように変更。
  - **検証**: Geoguessr ページで [ANALYZE] をクリックし、バックグラウンドに送られるペイロード内の「プロンプト」が、自分で設定したカスタムテキストになっているかログで確認。 [DONE]

---

## Phase 5: エンドツーエンドの最終自動検証
**目標**: プロンプトの変更から Gemini への入力までが、一気通貫で 100% 正しく動作することを自動で実証する。

- **Step 5.1: 統合自動テストの実行**
  - **検証手順**:
    1. 拡張管理画面でリロード。
    2. Popup 画面を自動操作し、特異な日本語（例：「★検証用プロンプト★ {{url}}」）を入力して保存。
    3. Geoguessr サマリーページで [ANALYZE] を実行。
    4. 自動遷移した Gemini ページにて、入力エリアに上記テキストが正確に（文字化けなく）流し込まれていることを DOM 取得により証明。
  - **成功基準**: Gemini の入力エリアの `innerText`（または相当する値）が設定値と完全に一致すること。 [DONE]

## Phase 6: Options Page への移行と URL 共通設定 [NEW]
**目標**: ポップアップから広い設定ページ (Options Page) へ機能を移設し、map-making.app の URL をユーザーが自由に（かつ一つに）設定できるようにする。

- **Step 6.1: Options Page の基盤作成**
  - **実装**: `options.html` と `options.js` を作成。`manifest.json` に `options_page` を登録。
  - **検証**: 拡張機能の「オプション」またはポップアップのリンクから、日本語の設定ページが開くことを確認。

- **Step 6.2: map-making.app URL の Storage 管理化**
  - **実装**: `constants.js` に `MAP_BASE_URL` キーを追加し、Storage に初期 URL（Result Map URL）をセットする処理を追加。
  - **検証**: `chrome.storage.local` から設定した URL が取得できることをコンソールで確認。

- **Step 6.3: background.js の URL 動的参照化**
  - **実装**: `VIEWER_URL_BASE` や `resultUrl` をハードコードから変更し、Storage から取得した URL を使用するように修正。
  - **検証**: URL をわざと書き換えて `chrome.storage.local.set` し、[ANALYZE] 実行時にその新しい URL でページが開くことを確認。

- **Step 6.4: UI の整理と最終統合**
  - **実装**: ポップアップを「設定を開く」ボタン主体のシンプルなものに変更。`options.js` にプロンプト編集ロジックを移設。
  - **検証**: 新しい Options ページでプロンプトと URL を編集・保存し、Geoguessr -> Map (Capture) -> Gemini (Result) の全フローが正常に完了することを実証。
