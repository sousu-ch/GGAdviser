# PROMPT IMPROVEMENT ANALYSIS

現在のシステムプロンプト（`constants.js`）を分析し、よりAIの出力精度を高め、コード側での処理を堅牢にするための改善案をまとめました。

## 1. 現状の強み (Keep)
*   **ロールプレイの明確化**: "トッププロプレイヤー兼コーチ" という役割定義が、解説のトーンを適切に設定している。
*   **構造化された出力**: `## ■ 1.` などのヘッダーにより、可読性が高く、将来的にはプログラム的な解析も容易。
*   **具体的な制約**: 「iNaturalist準拠」「Gen2/3/4判定」など、専門的な指示が含まれており、GeoGuessr特有のニーズを満たしている。
*   **[画像N: Grid] 形式の導入**: これによりテキストと画像の強力なリンク付けが可能になっている。

## 2. 潜在的な課題 (Issues) & 改善案 (Improvements)

### A. ハルシネーション（幻覚）の抑制
**課題**: 入力データとして正確な「正解座標」を与えているため、AIが画像を見ずに「その場所の知識（国勢調査データや歴史など）」を語ってしまうリスクがある。
**改善案**:
> 「あくまで **提供されたスクリーンショットに映っている視覚情報のみ** を根拠に推論してください。画像から読み取れない外部知識（歴史的背景や統計データなど）による特定は避けてください。」
という制約を追加する。

### B. グリッド参照のタイミング
**課題**: AIが説明の冒頭で `[画像1: A-1]` を置いてしまい、何に対する参照かわかりにくくなる場合がある。
**改善案**:
> 「対象物（看板、植物など）について言及した **直後** に参照を置いてください。文頭や文脈と無関係な場所には置かないでください。」
という配置ルールをより厳格化する。

### C. 方角への言及不足
**課題**: ユーザーは「北側の画像」を見ているのかわからない場合がある。
**改善案**:
> 「『北側の道路には... [画像1: A-1]』のように、可能な限り **方角（北・東・南・西）** も文脈に含めて説明してください。」
と指示し、空間的な理解を助ける。

### D. 不確実性の明示
**課題**: 些細な草の生え方などを無理やり「特定根拠」として断定してしまう可能性がある。
**改善案**:
> 「決定的な証拠がない場合は、『推測の域を出ないが』や『可能性が高い』といった表現を用い、過度な断定を避けてください。」
を追加する（ただし、プロのコーチという設定とのバランスが必要）。

## 3. 具体的な変更案のドラフト

各セクションに以下のような追記を検討します。

**【制約事項】への追加案:**
```markdown
6. **視覚的根拠の厳守**: 正解座標から得られる外部知識（歴史、統計）ではなく、必ずスクショ内の視覚情報（Visual Evidences）に基づいた論理展開を行ってください。
7. **方角の明示**: どの方向の景色について語っているか（北・東など）を積極的に文中に含めてください。
```

**【回答フォーマット】への微調整:**
```markdown
- **主要メタ判定**: [例: 北向きの広角カメラ [画像1] (★★★)]
```
のように、メタ情報にも方角や画像番号を必須化する例示を増やす。

---
**結論**:
現状でも十分機能していますが、特に「視覚情報のみに基づく」という制約は、AIが座標知識に引っ張られすぎるのを防ぐために重要かと思われます。
