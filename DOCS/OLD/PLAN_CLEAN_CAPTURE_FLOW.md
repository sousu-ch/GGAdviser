# 実施計画書：キャプチャフローのリファクタリング（URL汚染の防止）

## 1. 目的
ストリートビュー撮影（キャプチャ）用タブを開く際、URLハッシュパラメータ（例: `#gg_capture=true&gg_lat=...`）を使用する現在の方式を廃止します。代わりにメッセージ通信ベースの初期化を採用することで、URL汚染を防止し、ホストサーバー側での検知リスクを低減させます。

## 2. 実装方針
- **プル型ハンドシェイク:** 背景スクリプトからデータを一方的に送りつけるのではなく、タブ側から「準備完了（MAP\_TAB\_READY）」を報告させ、それを受けて背景スクリプトが初期化データ（INIT\_PANO）を送る堅牢な方式を採用します。
- **クリーンURL:** `chrome.tabs.create` 時にはハッシュを含まない純粋なURLのみを使用します。
- **明示的なモード指定:** メッセージ内で `mode: 'capture'` を明示し、プログラムがURLに頼らずに動作モードを識別できるようにします。

## 3. 工程表

### 工程 1: 通信プロトコルの定義とハンドシェイクの実装 [x]
**目標:** 背景スクリプトとコンテンツスクリプト間での確実な通信を確立する。

- [x] `PanoBridge.js` の `init()` 時に、背景スクリプトへ `MAP_TAB_READY` を報告する処理を追加。
- [x] `background.js` の `handleMessage` に `MAP_TAB_READY` のハンドラを追加し、待機中のキャプチャ状態があれば `INIT_PANO` を送り返す。
- [x] **検証ポイント:** 
    - [x] マップタブを開いた際、コンソールに「MAP\_TAB\_READY (Pull)」等のログが表示されること。
    - [x] 背景スクリプトが正しくメッセージを認識し、データの送信準備ができること。

### 工程 2: URL汚染の排除（タブ作成ロジックの修正） [x]
**目標:** 撮影用タブをクリーンなURLで開く。

- [x] `background.js` の `startSequentialCapture` 内で構築するURLからハッシュパラメータを削除。
- [x] `PanoBridge.js` 内の `checkHashForConfig`（URLハッシュによる自動起動）への排除。
- [x] **検証ポイント:**
    - [x] キャプチャ開始時、ブラウザのアドレスバーにパラメータが含まれていない（きれいなURLである）こと。

### 工程 3: メインワールド・スクリプト（inject_main.js）の修正 [x]
**目標:** メッセージからの指示に基づいて撮影用オーバーレイを表示する。

- [x] `inject_main.js` の `initPano` を修正し、引数のデータに含まれる `mode` に基づいて `isCapture` を判定するように変更。
- [x] 座標設定とオーバーレイ表示のタイミングを調整し、画面が真っ暗にならないよう確実にリサイズをトリガーする。
- [ ] **検証ポイント:**
    - メッセージを受信後、即座にフルスクリーンのストリートビュー（黒背景のオーバーレイ）が表示されること。

### 工程 4: 撮影シーケンス（回転処理）の安定化 [x]
**目標:** 0° -> 90° -> 180° -> 270° の回転が確実に完走するようにする。

- [x] `inject_main.js` にて、`tilesloaded` イベント（描画完了）を確実に検知し、背景スクリプトへ `MAP_READY_FOR_Clean` を送る。
- [x] 万が一描画イベントが来ない場合に備え、1.5秒程度のセーフティタイマーによる強制進行ロジックを導入。
- [x] **堅牢性の向上:** キャプチャ用オーバーレイに現在のステータス（例: "Capturing North..."）を表示する機能を追加。
- [x] **ユーザ通知:** 全てのキャプチャが完了した際にブラウザ通知（Desktop Notification）を表示。
- [x] **検証ポイント:**
    - [x] 最初の1枚を撮影後、自動的に次の角度へ回転し、全4枚が正しくキャプチャされること。
    - [x] コンソールを開かなくても、画面上の表示で進捗がわかること。

## 4. 全体検証プロセス

1. **初期状態確認:**
   - 拡張機能をリロードし、既存のキャプチャデータやキャッシュがない状態にする。
2. **GeoGuessr からの起動:**
   - GeoGuessr のプレイ画面で [ANALYZE] ボタンを押下。
3. **タブ転送の確認:**
   - `map-making.app` のタブが「クリーンなURL」で開くことを目視で確認。
4. **キャプチャ動作の観察:**
   - タブがロードされた後、数秒以内にフルスクリーン表示に切り替わり、回転が始まるかを確認。
5. **最終結果の確認:**
   - Gemini 側に4枚の画像と推論プロンプトが正しく送られ、解析が始まることを確認。
