# プロンプト改良とリンク解析強化の提案

現状の課題：Geminiが `[画像1: C-1, 画像3: C-2]` や `[画像1: C-1, C-2]` のような複合フォーマットを出力し、リンク化に失敗する。

これに対処するための「プロンプトによる抑制案」と「コードによる対応案」を提示します。

## アプローチ A: プロンプトによる制御（即効性あり）

Geminiに対して、常に「単一のリンク形式」で出力するよう指示を強化します。`constants.js` の `DEFAULT` プロンプト内の「制約事項」を修正します。

**変更案（diff）:**

```diff
- 1. **グリッド参照の必須化**: 特筆すべきオブジェクト（看板、ポール、特徴的な植生など）を指摘する際は、必ず「看板 [画像1: A-2]」や「凹凸の緩やかな山並み [画像3: C-3]」のように、**説明の直後に画像番号とグリッド座標**を付記してください。
+ 1. **グリッド参照の厳格化**: オブジェクトを指摘する際は、必ず「看板 [画像1: A-2]」のように記述してください。
+    - **禁止**: `[画像1: A-1, A-2]` や `[画像1: A-1, 画像2: B-2]` のような「まとめ書き」は禁止です。
+    - **推奨**: 複数の箇所を指す場合は `[画像1: A-1] と [画像1: A-2]` のように、必ず **1つの括弧に1つの座標** を入れて分割してください。
```

**メリット**:
- コード変更なしで試せる。
- AIの出力が明確になる。

**デメリット**:
- AIが指示を無視する可能性がゼロではない。

---

## アプローチ B: JavaScript (Regex) の強化（根本解決）

AIがどうしてもまとめて書いてしまう場合に備え、`ImageInjector.js` の正規表現ロジックを改良し、複合フォーマットも解釈できるようにします。

**対応可能なパターン:**
1. `[画像1: A-1, A-2]` -> 同じ画像の複数座標
2. `[画像1: A-1, 画像2: B-2]` -> 複数の画像と座標

**ロジック変更イメージ:**

現在の正規表現:
```javascript
/\[(?:画像|Image)?(\d+)\s*:\s*([A-Z0-9-]+)\]/
```

変更案のロジック（擬似コード）:
1. まず `\[(.*?)\]` で括弧内を大まかにキャプチャする。
2. その中身をカンマ `,` で分割する。
3. 分割された各パーツについて、「画像番号」と「座標」を再解析する。
   - `画像1: A-1` -> Image:1, Coord:A-1
   - `A-2` (省略形) -> 直前のImage番号を引き継いで Image:1, Coord:A-2

**メリット**:
- AIが多少フォーマットを崩してもリンク化できる（ユーザー体験が良い）。

**UXの挙動 (Q&A):**
- **Q**: `[画像1: A-1, 画像2: B-2]` のように複数含まれていたらどう表示する？
- **A**: 正規表現で内部を分割し、**独立した2つのアイコン** を横並びで生成します。
  - 表示: `[🍊画像1] [🍊画像2]`
  - 動作: それぞれのアイコンが独立して機能し、クリックされた方の画像を表示します（一度に2枚開くわけではありません）。

## 推奨プラン

**アプローチ A（プロンプト変更）と B（コード強化）の両方を行うこと** を推奨します。

1. **Phase 1: プロンプト変更**
   - まずプロンプトで「きれいな出力」を促し、基本品質を上げる。
2. **Phase 2: コード強化**
   - それでも発生する表記ゆれ（`A-1, A-2`など）を拾えるようにコードをアップデートする。

今回は「プロンプトの変更をしたい」というご要望ですので、まずは **アプローチ A** の内容で `constants.js` を修正することを提案します。
