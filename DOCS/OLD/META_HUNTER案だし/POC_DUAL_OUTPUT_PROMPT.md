# PoC: Dual-Output（解説＋データ）プロンプトの実証

「解説テキストとシステム用JSONを両立できるか？」という疑問に対する回答と、具体的なプロンプト設計案です。

## 結論

**十分に可能です。**
現代のLLM（特にGemini 1.5/2.0クラス）では、「まずは人間に分かるように考えを述べよ (Chain of Thought)、その後にその結果をJSONにまとめよ」という指示が最も精度が高くなる定石です。

---

## プロンプト設計案

システムプロンプトの末尾に、以下の指示を追加します。

```markdown
...(既存の分析指示)...

## 出力フォーマットの要件
1. まず、ユーザー向けの自然な日本語で、推測の根拠と結論を詳しく解説してください。
2. 解説の最後に `---METADATA_START---` という区切り線を入れてください。
3. その後に、**解説の中で言及したすべての「決定打（ヒント）」** を、以下のJSON形式で出力してください。

### JSON Schema
```json
{
  "clues": [
    {
      "image_index": 1,          // 画像番号 (1-4)
      "coordinates": ["A-1"],    // 関連するグリッド (配列)
      "short_title": "電柱のプレート",  // ポップアップ用の短い見出し (10文字以内)
      "detail": "この黄色と黒の縞模様は台湾特有のものです。", // 解説文 (要約)
      "importance": 3            // 重要度 (1-3)
    },
    ...
  ]
}
```

## この構成のメリット

1.  **整合性がとれる**: AIは「自分で書いた解説」を要約してJSONにするため、解説文とJSONの内容（座標など）が矛盾しにくくなります。
2.  **既存機能への影響なし**: 既存のアプリは `---METADATA_START---` より前の部分だけを切り取って表示すれば、今まで通りの「解説ビュー」として機能します。
3.  **新機能（ゲームモード）**: 裏でJSONをパースすれば、「画像1のA-1」を光らせ、クリックしたら `detail` を表示する「ハンターモード」が即座に生成できます。

このように、「人間用の思考」と「機械用のデータ」を1回のレスポンスにパックすることは、現在のAI開発においては非常に標準的かつ強力な手法です。
