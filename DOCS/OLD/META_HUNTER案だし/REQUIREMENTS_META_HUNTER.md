# 要件定義: Meta Hunter Mode (探索型学習モード)

ユーザー様の問いに基づき、「画像から情報を探索する」体験を実現するための詳細仕様案です。

---

## 課題1: 初期画面の構成 (4枚の画像表示)

**課題**: 4枚を同時に詳細表示するには画面が狭すぎる。かといって1枚ずつ切り替えるのは「どこにヒントがあるか」が分からずストレスになる。

**解決案: 「俯瞰 (Overview) -> 没入 (Focus)」の2段階UI**

1.  **初期状態: コックピット・ビュー**
    *   画面中央にメイン画像、下部（または横）に残り3枚のサムネイルを表示。
    *   **重要**: 各サムネイルには「**ヒントバッジ (Hint Badge)**」を表示する。
        *   例: [北]のサムネイルの右上に「🔴 3」バッジ（ここにヒントが3つあるよ、という合図）。
    *   これにより、ユーザーは「あ、北画像に重要な情報が集まってるな」と直感的に判断し、北画像をクリックして拡大できる。

2.  **探索状態: フォーカス・ビュー**
    *   選択した1枚を大きく表示。ここで初めて「グリッド上の光る枠」が見えるようになる。

## 課題2 & 3: プロンプト設計とデータ関連付け

**課題**: 自然言語の解説文から「どのボタンを押したら何が出るか」を正確にマッピングするのは、Regexだけでは限界がある（誤爆やズレのリスク）。

**解決案: JSON出力プロンプト (Structured Output)**

解説用の自然言語とは別に、システム読み取り専用の**JSONデータ**を出力させます。

**推奨プロンプト構成:**
> （前略...通常の解説を出力...）
>
> 最後に、以下のJSONフォーマットで「探索ポイント」を出力してください。
> ```json
> {
>   "clues": [
>     {
>       "image_index": 1, 
>       "grid": "A-2",
>       "short_label": "特徴的な電柱",
>       "full_explanation": "この「はしご型」のステップはフランス独自のものです。",
>       "importance": 3
>     },
>     ...
>   ]
> }
> ```

**データ関連付けのロジック:**
*   **Grid**: 画像のグリッド位置 (`A-2`)。
*   **Label**: マウスホバー時に一瞬出る短いタイトル。
*   **Explanation**: クリック時に表示される詳細解説。

この方式なら、**「座標」と「表示すべきテキスト」が1対1で強固に紐づく**ため、プログラム側での制御が確実になります。

## 課題4: UIデザイン案

具体的に「どう遊ぶか」のUI案です。

### 【案1】没入型オーバーレイ (Immersive Hunter) - 学習効率重視

「画像から目を離さずに学習する」ことに特化したスタイル。

*   **動作**:
    1.  画像上に「金色の枠（未回収のヒント）」が点滅している。
    2.  ユーザーが枠をクリック。
    3.  **その場所から吹き出し (Popover)** が直接出る。
        *   *「これはフランスの電柱」*
    4.  枠の色が「青（回収済み）」に変わる。
*   **メリット**: 視線移動がゼロ。直感的。
*   **根拠**: Google MapsのPOI（店舗情報）クリックと同じ体験であり、馴染み深い。

### 【案2】コレクターズ・リスト (The Collector) - ゲーム性重視

「ヒントを集めて図鑑を埋める」感覚を強調したスタイル。

*   **動作**:
    1.  画面右側に「ヒントリスト」があるが、**全てモザイクがかかっている**（または「Secret ???」と表示）。
        *   `[???] ★★★`
        *   `[???] ★☆☆`
    2.  画像上の光るグリッドをクリックする。
    3.  「正解！」というエフェクトと共に、リストの該当項目がアンロックされ、詳細が表示される。
        *   `[電柱] フランスのはしご型 ★★★`
*   **メリット**: 「あと3つ残っている」という達成感が可視化され、コンプリート欲求を刺激する。
*   **根拠**: アドベンチャーゲームの探索パートや、実績解除システムに近い。学習のモチベーション維持に強い。

---

## 推奨される構成

**UI案2「コレクターズ・リスト」** をベースにしつつ、クリック時の挙動は **案1のようなポップアップ** を併用するのが最強だと思われます。

1.  **右サイドバー**: 「未発見のヒント数」と「モザイクのリスト」を表示（進行度管理）。
2.  **メイン画面**: グリッドをクリックすると、その場でポップアップ解説（直感的な学習）。同時にサイドバーのリストも埋まる（達成感）。

この「**探索と収集**」のハイブリッド構成で要件定義を進めてはいかがでしょうか？
JSONプロンプトへの移行が必要になりますが、体験の質は劇的に向上します。
