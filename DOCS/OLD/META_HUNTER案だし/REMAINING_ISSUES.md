# 残課題と決定事項: Meta Hunter Mode

実装フェーズ（Execution）に移る前に、決めておくべき仕様の「穴」と、技術的な課題点です。

## 1. UX/仕様上の決定事項

### A. 「場所のないヒント」の扱い (Global Clues)
**課題**: AIの解説には「特定の場所」を指さない全体的なヒント（例: 「ここは左側通行です」「空が北半球っぽいです」）も含まれます。これらをMeta Hunter Modeでどう表現するか？
*   **案1**: **「全域グリッド」** - 画像全体を囲むような大きな枠を用意する？
*   **案2**: **「基本情報カード」** - 画面の隅に常に表示される「基本メタ」枠を作る？（推奨）

### B. 永続性とリセット (Persistence)
**課題**: ブラウザをリロードした時、集めた「ハンター実績（アンロックしたヒント）」はどうなるか？
*   **案1**: **リセット** - あくまでその場のプレイ用。リロードしたら最初から。
*   **案2**: **保存** - `localStorage` に保存し、リロードしても「収集済み」状態を維持する。（実装コスト増）

### C. 「不正解」の扱い
**課題**: ユーザーが「光っていない（ヒントがない）グリッド」をクリックした時の挙動。
*   **案1**: **無反応**。
*   **案2**: **「そこには何もないようだ」** と表示。（ゲーム的）
*   **案3**: 自分でメモを書けるようにする？（過剰機能か）

---

## 2. 技術的・実装上の課題

### A. JSONパースの堅牢性 (Error Handling)
**課題**: AIはたまにJSONの構文ミス（カンマ忘れなど）をします。
*   **対策**: `JSON.parse` が失敗した場合のフォールバック処理。
    *   失敗時は「ハンターモード」ボタンを非活性にするか、「テキスト解析による簡易生成」に切り替えるか（後者は実装が大変）。
    *   **結論**: エラー時は「解説ビューのみ利用可能」と割り切り、エラーログを出すのが現実的。

### B. 座標の「ズレ」許容範囲
**課題**: AIが「A-1」と言ったが、実際の重要物体が「A-1とA-2の境界」にある場合。
*   **対策**:
    *   クリック判定を広めにする（周辺8マスも反応させる？）。
    *   あるいは、AIに `["A-1", "A-2"]` と複数指定させることを徹底する。
