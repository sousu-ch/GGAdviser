# 実装計画書セルフレビュー・チェックリスト

計画書（`PLAN_*.md`）を作成または更新した際は、**ユーザーに提示する前に**必ずこのリストを用いて自己レビューを行ってください。
すべての項目にチェックが入らない場合、計画書を修正する必要があります。
このファイル自体はサンプルです。このファイルを直接編集しないように注意してください。

## 1. 構造とフォーマット
- [ ] タイトルは具体的か？（曖昧な「機能追加」ではなく「〇〇機能の実装」など）
- [ ] `TEMPLATE_PLANNING.md` のフォーマット（標準Markdown）に従っているか？
- [ ] フェーズ（Phase）分けは適切か？（1つのフェーズが大きすぎないか）

## 2. 実装ステップの具体性
- [ ] 各ステップに `[実装]` と `[検証]` の両方のチェックボックスがあるか？
- [ ] 「実装」の内容は具体的か？（「〇〇を修正」だけでなく、対象ファイルや関数名が想定されているか）
- [ ] 「検証」の手順は具体的か？（「動作確認する」だけでなく、「DevToolsで〇〇を確認」「ログに△△が出ることを確認」など）

## 3. 検証ゲート（Verification Gate）の厳格化 【最重要】
- [ ] **各ステップの終わり**に必ず「Verification Gate」が設置されているか？
- [ ] Gate には以下の文言（または同等の厳しい条件）が含まれているか？
    > 「検証結果の証拠（ログ、スクショ等）を提示し、ユーザーに動作確認を依頼する。」
    > 「ユーザーの承認を得るまで、次のフェーズの実装は絶対に行わない。」
- [ ] 曖昧な完了条件（「問題ないことを確認する」等）になっていないか？

## 4. リスクと一貫性
- [ ] 既存機能（特にユーザーが重視している機能）を破壊する可能性について考慮されているか？
- [ ] `task.md` との整合性は取れているか？（`task.md` にも同じフェーズ区分が反映される予定か）

---

**使用方法:**
AI は計画書作成後、思考プロセス（`think`）または実際の応答内でこのリストを順にチェックし、「全てクリア」を確認してからユーザーに計画書を提示すること。
