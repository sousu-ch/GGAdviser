# AI Agent Planning Template (v2.2)

あなたが新しい機能を実装するための計画書を作成する際は、**必ず**以下の手順とフォーマットに従ってください。

## 🧠 Step 0: Pre-Planning & Gate Rules

計画書（Markdown）を出力・実行する**前に**、以下のルールを厳守すること。

1.  **疎結合な細分化**: 各ステップは独立して検証可能であること。
2.  **進捗管理の明示**: 
    - 未着手=`[ ]`, 作業中=`[/]`, 完了=`[x]` を使用して進捗を明示する。
    - 各ステップ内には、**[実装]** と **[検証]** それぞれにチェックボックスを設ける。
3.  **フェーズ・ゲート制**:
    - Phase N の全ステップ（実装・検証の両方）が完了し、証拠を添えてユーザーから承認を得るまで、Phase N+1 のコードを書いてはならない。

---

## 📝 計画書フォーマット (Markdown)

```markdown
# [プロジェクト/機能名] 実装計画書

## 1. 目的とゴール
(何を解決するのか、何ができるようになるのか)

---

## 2. 実装フェーズ (Implementation Phases)

**進捗状況の更新**: 未着手=`[ ]`, 作業中=`[/]`, 完了=`[x]`

### Phase 1: [フェーズ名]
**目的**: (このフェーズで達成すること)

- [ ] **Step 1-1: [タスク名]**
    - [ ] **[実装]**: 
        - [ファイル名] の [関数名] を修正。
    - [ ] **[検証]**: 
        - [操作] を行い、**期待される結果**（[詳細]）になることを確認する。
        - **確認方法**: [DevTools、ログなど]
        
- [ ] **Step 1-1 Verification Gate**: 
1. Step 1-1の実装・検証を完了させる。
2. **検証結果の証拠（ログ、画像など）を提示し**、ユーザーに動作確認を依頼する。
3. ユーザーの承認を得るまで、**Step 1-2 の実装は絶対に行わない。**

- [ ] **Step 1-2: ...**
    - [ ] **[実装]**: 
        - [ファイル名] の [関数名] を修正。
    - [ ] **[検証]**: 
        - [操作] を行い、**期待される結果**（[詳細]）になることを確認する。
        - **確認方法**: [DevTools、ログなど]
        
- [ ] **Step 1-2 Verification Gate**: 
1. Step 1-2の実装・検証を完了させる。
2. **検証結果の証拠（ログ、画像など）を提示し**、ユーザーに動作確認を依頼する。
3. ユーザーの承認を得るまで、**Step 1-3 の実装は絶対に行わない。**


### Phase 2: [フェーズ名]
...
```
